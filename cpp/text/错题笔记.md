# 408 真题练习 · 易错点笔记

记录练习真题过程中真实出现过的错误，考前对照自检。

---

## 一、参数传递：值传递改不了实参

**2009 / 2010 都踩过**

```cpp
void swap(int a, int b) {   // ❌ 交换的是副本
    int k = a;
    a = b;
    b = k;
}
int R[5] = {0,1,2,3,4};
swap(R[0], R[1]);           // R 一个元素都没变
```

**要点**：C++ 普通形参是副本。要让函数修改调用方的变量，必须用引用 `int &a`，或者直接传指针 `int *`（用 `*a` 解引用）。

```cpp
void mySwap(int &a, int &b) { ... }   // ✅
```

**症状识别**：算法思路看着对、过程也走了，但数组"完全没变化"——先查是不是值传递。

---

## 二、循环里「绝对下标」和「相对长度」不能混用

**2010 的 `S` 函数，错了两次**

```cpp
void S(int *R, int l, int r) {
    for (int i = l; i < (r - l + 1) / 2; i++)   // ❌
        mySwap(R[i], R[r - i]);
}
```

两个独立的错误：

| 错误 | 说明 |
|---|---|
| 起点是 `l`（绝对），条件是长度的一半（相对） | `l=1, r=3` 时条件是 `i < 1`，而 `i` 从 1 开始 → **一次都不执行** |
| 配对写成 `R[r-i]` | 只在 `l=0` 时碰巧正确；`l>0` 时应配 `R[l+r-i]` |

**正确写法**：`i` 只数"第几对"，下标现算

```cpp
for (int i = 0; i < (r - l + 1) / 2; i++)
    mySwap(R[l + i], R[r - i]);
```

**通用规律**：写循环前先明确一个变量代表什么——
- `i` 表示**第几个**（从 0 数）→ 访问用 `a[l + i]`
- `i` 表示**下标**（从 l 数）→ 边界用 `l + count`

同一条 `for` 里两种含义只能选一种，混用必错。

## 三、闭区间的边界是 `n-1`，不是 `n`

**2010 的 `ans`**

```cpp
S(R, p, n);      // ❌ 越界，S 内部会访问 R[n]
S(R, 0, n-1);    // ✅
```

数组有效下标 `0 ~ n-1`。凡是函数参数按**闭区间 `[l, r]`** 设计，传进去的 `r` 必须是最后一个元素的下标。

**症状识别**：测试时不崩溃，但结果不对，或者改坏了别的变量——这是未定义行为最典型的表现。

## 四、带头结点链表的下标语义

**2009 的 `ans`**

`head` 是**头结点**（哨兵，data 不存数据），第一个数据结点是 `head->link`。

```cpp
Node *p = head;   // p 从哨兵出发
Node *q = head;
```

这种写法的好处：`p` 比 `q` 落后 k 格，`q` 走到 NULL 时 `p` 正好落在倒数第 k 个**数据结点**上，哨兵自身不会被当成答案。

**要点**：用哨兵起步，就永远差一格；这个"差一格"正是我们要的偏移量。若从 `head->link` 起步，也可以，但边界判断要另算。

## 五、非法输入导致的空指针解引用

**2009 的 `ans`，k = 0 时崩溃**

```cpp
while (q != NULL) {
    q = q->link;
    p = p->link;      // k=0 时 p、q 同步前进，一起变成 NULL
}
cout << p->data;      // ❌ 解引用空指针 → 段错误
```

题面写的是"k 为正整数"，严格说不算错；但加一行护栏成本为零：

```cpp
if (head == NULL || k <= 0) return 0;
```

**要点**：只要循环里有"两个指针同速前进"，就要想清楚它们会不会同时到达 NULL。

## 六、`typedef struct` 在 C++ 里是多余的

```cpp
typedef struct Node {   // ❌ typedef 后面没有名字
    int data;
    Node *link;
};                      // g++ 警告：'typedef' was ignored in this declaration
```

C++ 里 `struct Node { ... };` 之后，`Node` 已经是类型名，不需要 `typedef`。

## 七、自定义 `swap` 与 `std::swap` 重名

```cpp
using namespace std;          // std::swap 也进入候选
void swap(int a, int b);      // 与你自己的版本重名
```

现在能编过（值传递版是普通函数，优先级高于模板），但**签名一旦变化就会静默选错版本**。

**建议**：自定义函数改名 `mySwap`，或直接删掉，用 `<utility>` 的 `std::swap`（自带引用，效率更高）。

## 八、测试方法：穷举 + 哨兵 + 识别假通过

**2009 与 2010 的实测对比**

| 测试方式 | 结果 |
|---|---|
| 只测一个用例（n=5, p=2） | 2010 **看起来通过**（其实那次碰巧对） |
| 穷举 n=2~10、p=1~n-1 共 45 组 | 立刻暴露 37 个失败 |

两个典型的**假通过**：

1. **p = n-1**：`[p, n-1]` 长度只有 1，本来就不用逆置，函数错了也看不出来
2. **全部元素相同**：换不换都一样，恒通过

**三条测试习惯**

1. **穷举小规模**：n 取 2~10，p 取遍 1~n-1，几行循环就能覆盖所有边界
2. **哨兵检测越界**：数组开大一点，`n` 之后填一个特殊值，跑完检查有没有被改写

   ```cpp
   const int SENTINEL = -999;
   for (int i = 0; i < CAP; i++) R[i] = SENTINEL;
   // ... 执行算法 ...
   for (int i = n; i < CAP; i++)
       if (R[i] != SENTINEL) cout << "发生越界写入";
   ```

3. **小函数单独测**：`S` 这么短的函数，直接 `int a[5]={1,2,3,4,5}; S(a,1,3);` 看结果，比整题一起跑更容易定位

## 九、归并求中位数：三个坑

**2011 真题**：两个各 n 个元素的升序序列，共 2n 个，求中位数。

### ① "第 n 小" 对应下标 `n-1`，不是 `n`

| 说法 | 下标 |
|---|---|
| 第 1 小 | `C[0]` |
| 第 n 小 | `C[n-1]` |

原代码 `return C[n];` 取的是第 n+1 小，**所有用例都差一位**。

**识别信号**：结果总是差 1，先怀疑"第几小 ↔ 下标"的换算，而不是算法思路。

### ② 归并循环必须同时判两条序列

```cpp
while(k < n+1){                 // ❌ 只判了合并进度
    if(A[i] < B[j]) ...
}
```

一旦 A 的全部元素都小于 B（`i` 走到 `n`），下一轮就会读 `A[n]`——越界读栈上的随机值，**有时看着对有时错**，是最难查的一类 bug。

标准归并是三段式：

```cpp
while (i < n && j < n) { 谁小取谁 }
while (i < n) { 搬完 A }
while (j < n) { 搬完 B }
```

### ③ 变长数组 `int C[n+1]` 不是标准 C++

`-Wvla` 警告。练习中一律用固定大小数组（如 `int C[200]`）或 `new int[2*n]`。

### ④ 暴力解 O(n) 空间没问题，但要知道更省的写法

| 写法 | 时间 | 空间 | 特点 |
|---|---|---|---|
| 归并存数组，取 `C[n-1]` | O(n) | O(n) | 最直观，不容易写错，考场首选 |
| 双指针数到第 n 个（不存结果） | O(n) | O(1) | 只用一个 `cur` 记录当前值 |

## 十、链表找公共后缀：返回值与控制流

**2012 真题**：两个带头结点的单链表，找共同后缀的起始结点。

### ① 返回类型要匹配题目要的"位置"

```cpp
Node ans(Node *str1, Node *str2) {   // ❌ 返回结点本身
    ...
    return *p;                        // ❌ 返回的是副本
}
```

题面要的是**共同后缀的起始位置**，即结点指针：

```cpp
Node *ans(Node *str1, Node *str2) { ... return p; }
```

`*p` 是解引用，拿到的是结点副本。后果：调用方无法在原链表里定位该结点，也没法用 `NULL` 表示"没找到"。

**规律**：题目说"位置 / 指针 / 结点"，返回 `Node *`；说"值"，返回 `int`。写函数头之前先确定这一点。

### ② 循环结束后必须有出口

```cpp
while (p != NULL) {
    if (p == q) return p;
    p = p->next;
    q = q->next;
}
}                    // ❌ 没有 return，控制流直落函数末尾
```

两个单词可能没有公共后缀，循环自然结束时必须 `return NULL;`。

编译器会给出 `warning: control reaches end of non-void function`——**这条警告就是在告诉你漏了分支**，不要只看 error 不看 warning。

### ③ 拼写错误：读编译器的建议

```
error: 'nq' was not declared in this scope
note: suggested alternative: 'n2'
```

`nq` 是 `n2` 的手误。g++ 的 `note:` 行经常直接给出正确答案，遇到 `not declared` 先看这一行。

### ④ 判断"同一个结点"必须比较地址

```cpp
if (p == q) return p;        // ✅ 地址相同才是同一个结点
if (p->data == q->data)      // ❌ 值相同不代表共享存储
```

测试用例"两条链表都是 `1 2 3`，但各自独立"就是为了抓这个错——用值比较会误判成有公共后缀。

### ⑤ 长度差对齐的两个分支都要测

```cpp
if (n1 > n2) { 长 1 侧的 p 先走 n1-n2 步 }
else         { 长 2 侧的 q 先走 n2-n1 步 }
```

只测"str1 更长"会漏掉 `else` 分支。至少准备四组：str1 长、str2 长、等长、一个为空。

## 十一、主元素：`n/2` 的整除边界

**2013 真题**：找出现次数超过 `n/2` 的元素，没有则输出 -1。这一题代码一次写对，记的是**容易写错的知识点**。

### ① `m > n/2` 里 `n/2` 是整除

| n | `n/2` | 主元素至少要出现 |
|---|---|---|
| 4 | 2 | 3 次（`3 > 2`） |
| 5 | 2 | 3 次（`3 > 2`） |
| 6 | 3 | 4 次（`4 > 3`） |

所以 `if (Count[x] > n / 2)` 是正确写法，**不要**改成 `>= n/2`——那样 n=4、出现 2 次的元素会被误判成主元素。

边界用例必备：`{1,1,2,2}`（n=4，各占一半）应返回 -1。

### ② 计数数组的大小与越界

```cpp
vector<int> Count(n + 1);      // 大小取决于值域，不是长度
Count[A[i]] ++;                // operator[] 不做越界检查
```

2013 原题限定 `0 ≤ ai < n`，所以 `Count(n)` 就够。**一旦值域超出这个范围，这行就是越界写**，会破坏内存。做题时先看值域，再定数组大小。

### ③ 可以边计边判

不必等全部统计完：

```cpp
Count[A[i]]++;
if (Count[A[i]] > n / 2) return A[i];   // 一过半立刻返回
```

最坏情况仍是 O(n)，但平均更早结束。

### ④ 两种解法

| 解法 | 时间 | 空间 | 备注 |
|---|---|---|---|
| 计数数组（本题写法） | O(n) | O(n) | 最直观，依赖值域范围 |
| 摩尔投票法 | O(n) | O(1) | 标准答案的做法，先找候选再验证 |

题面只要求"时间上尽可能高效"，计数法 O(n) 已经达标。

## 十二、二叉树的 WPL：只算叶子，还要乘深度

**2014 真题**：求二叉树的带权路径长度 WPL。

```cpp
// 原错误写法
int ans(TreeNode *T) {
    int l = ans(T->left);
    int r = ans(T->right);
    return T->weight + l + r;      // ❌ 把所有结点的权值加起来
}
```

### ① 内部结点不计入

WPL 只累加**叶结点**（左右孩子都为空）。上面的写法把根、中间结点的权值也加进去了，结果偏大。

用 `10(5, 20(8,9))` 验算：正确值 `5×1 + 8×2 + 9×2 = 39`，错误写法得到 `10+5+20+8+9 = 52`。

### ② 叶子的权值要乘路径长度

WPL = `Σ (叶权值 × 根到该叶的路径长度)`。只加权值、不乘深度，是这题最常见的失分点。

### ③ 深度必须靠递归参数往下传

`ans(TreeNode *T)` 只有一个参数，装不下"当前在第几层"。标准做法是加辅助函数：

```cpp
int wpl(TreeNode *T, int deep) {
    if (T == NULL) return 0;
    if (T->left == NULL && T->right == NULL) return T->weight * deep;
    return wpl(T->left, deep + 1) + wpl(T->right, deep + 1);
}
int ans(TreeNode *T) { return wpl(T, 0); }
```

凡是要带"层数 / 路径长度 / 累加值"的树题，都用这个"主函数 + 辅助函数"的两层结构。

### ④ 路径长度按"边数"，根深度取 0

2014 原题写的是"从根结点到该叶结点所经过的**边数**"：

| 树 | WPL |
|---|---|
| 单结点（根即叶） | `weight × 0 = 0` |
| 根 + 一个叶 | `叶权值 × 1` |

按"层数"算（根为第 1 层）的教材会让单结点树得到 `weight`。**以题目定义为准**，取错起点会导致整棵树的结果全错。

### ⑤ 与 `countLeaves` 的关系

骨架和第 11 课的 `countLeaves` 完全一致，只把"叶子返回 1"换成"叶子返回 `weight × deep`"：

```cpp
if (T->left == NULL && T->right == NULL) return 1;            // countLeaves
if (T->left == NULL && T->right == NULL) return T->weight*deep; // WPL
```

## 十三、删除绝对值重复结点：指针与数组边界

**2015 真题**：带头结点的单链表，`|data| ≤ n`，绝对值相同的结点只保留第一次出现的。

思路正确（标记数组 + 双指针），改进的四处：

### ① 删除结点要 `delete`，且顺序不能错

```cpp
else{
    Node *del = p;       // 先记下要删的结点
    p = p->next;         // p 后移
    q->next = p;         // 前驱跨过它
    delete del;          // 再释放，否则内存泄漏
}
```

顺序关键：**先保存、再改指针、最后 delete**。若先 `delete p` 再 `p = p->next`，就是访问已释放内存。

### ② `const int MaxSize = 10000;` 才是标准数组

```cpp
int MaxSize = 10000;
bool N[MaxSize] = {false};        // ❌ VLA，-Wvla

const int MaxSize = 10000;
bool N[MaxSize] = {false};        // ✅ 编译期常量，标准数组
```

`-Wall` 不报这条，加 `-pedantic` 才暴露。VLA 在 GCC 下侥幸能编，换编译器或 n 过大就崩。

### ③ `abs` 的整数版在 `<cstdlib>`

```cpp
#include <cstdlib>        // 提供 int 版 abs
```

`<cmath>` 里是浮点重载，`<iostream>` 间接包含属于碰运气，和第 11 课 `max` 缺 `<algorithm>` 同类。

### ④ 标记数组大小 = 绝对值上界 + 1

```cpp
bool N[MaxSize];          // 有效下标 0 ~ 9999
```

`MaxSize = 10000` 意味着只支持 `|data| ≤ 9999`。若 `|data| = 10000` → 越界写。更贴题面的写法是按 n 分配：

```cpp
bool *N = new bool[n + 1]();     // 全 0
...
delete[] N;
```

用固定数组时，务必在注释里写明假定的上界。

### ⑤ 保序

题目要求"仅保留**第一次**出现"，所以保留的结点相对顺序不能变。用例 `{2,1,2,3,1}` 必须得到 `{2,1,3}`，不能变成 `{1,2,3}`。

### ⑥ 测试教训：对照实现也要覆盖同一值域

第一次跑测试时**测试程序自己崩溃**——暴力实现用了 `bool seen[200]`，而用例里有 `9999`，一进 `seen[9999]` 就段错误。

**对照实现的数组必须和被测代码支持的值域一致**，否则报的是"测试程序的错"，不是代码的错。现在已在测试里加了越界检查，超出时打印明确提示。

## 十四、乘积最大值：同一道题连错四版

**2025 真题**：对每个 `i`，求 `A[i]` 与另一个元素乘积的最大值，存入 `res[i]`。

这题换了四种写法，每次都栽在不同的地方，规律值得记住。

### 版一：想用快排把最值挪到两端

```cpp
Qsort(res, 0, n-1);
res[i] = max(A[i] * res[0], A[i] * res[n-1]);
```

- **快排的第二个 `while` 条件写反**（`A[i] >= pivot` 应为 `A[i] <= pivot`），左右在找同一类元素，最大值当枢轴时**死循环**
- 排序后 `res[i]` 是第 i 小，`A[i]` 是原数组第 i 个，**下标含义不同还混用**
- `res[0] *= res[0]` 变成自己乘自己，违反 `j ≠ i`

**教训**：排序会丢掉"原位置"信息，凡是结果要按原下标输出的题，别原地排序。

### 版二：从右往左扫，维护后缀极值

```cpp
for (int i = n-1; i >= 0; i--) {
    if (A[i] > 0) res[i] = A[i] * maxValue;
    else          res[i] = A[i] * minValue;
}
```

"正数乘最大值、负数乘最小值"这个规则本身是对的，但**只看到了右侧元素**：

- `i = n-1` 时右侧一个元素都没有，`minValue`、`maxValue` 都等于 `A[i]` 自己 → 自己乘自己
- 任何元素的最佳伙伴在左侧时都会算错

`{1,2,3}` 得到 `3 6 9`，正确答案是 `3 6 6`。

**教训**：单方向扫描只覆盖一半配对，先问自己"另一侧的元素怎么办"。

### 版三：双层循环全枚举

```cpp
for(int j = 0; j < n; j++) if(i != j)
    res[i] = max(res[i], A[i] * A[j]);   // res[i] 是垃圾值
```

思路对了，但：

- **文件少一个右大括号**，`expected '}' at end of input` 编译直接失败
- `res[i]` 未初始化就参与 `max`，垃圾值大时结果时对时错

**教训**：函数体的大括号先补齐再写逻辑；"取最大值"的累加器必须先给初值。

### 版四：改 `j = i+1` 只算一遍

```cpp
for(int j = i+1; j < n; j++)
    res[i] = max(res[i], A[i] * A[j]);   // ❌ 只更新 i
```

半枚举是对的（每对只算一次，乘法次数从 `n(n-1)` 降到 `n(n-1)/2`），但每对 `(i,j)` 是**两端共同的候选**：

```cpp
long long v = (long long)A[i] * A[j];
if (v > res[i]) res[i] = (int)v;
if (v > res[j]) res[j] = (int)v;        // ← 别只更新一边
```

只更新 `i` 的后果：`res[n-1]` 永远没被写入（它的伙伴全在左侧）。

另外 `int maxMul = A[i] * A[i];` 用"自己乘自己"作初值，同样违反 `j ≠ i`。

### 最终暴力版（已通过 3013 项测试）

```cpp
void calMulMax(int A[], int res[], int n){
    if (n < 2) return;
    for (int i = 0; i < n; i++) res[i] = INT_MIN;      // 初值
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++) {
            long long v = (long long)A[i] * A[j];
            if (v > res[i]) res[i] = (int)v;
            if (v > res[j]) res[j] = (int)v;           // 两端都更新
        }
}
```

时间 O(n²)、空间 O(1)。真题要求"尽可能高效"，O(n) 做法只需记录**最大、次大、最小、次小**四个值及其下标，排除自身后取 `max(A[i]×最大, A[i]×最小)`。

### 通用清单

- [ ] 结果要按原下标输出 → 不要原地排序
- [ ] 单方向扫描 → 检查另一侧是否被漏掉
- [ ] "取最大/最小"的累加器先给 `INT_MIN` / `INT_MAX`
- [ ] 半枚举 `j = i+1` → 记得同时更新 `res[i]` 和 `res[j]`
- [ ] `j ≠ i` 是题目要求 → 初值不能用 `A[i] * A[i]`
- [ ] 两数相乘 → 中间量用 `long long`

## 十五、重排链表 a1,an,a2,a(n-1)：四类错误

**2019 真题**：带头结点的单链表，重排为 `a1, an, a2, a(n-1), a3, ...`，要求空间 O(1)。

### 错法一：`||` 当成了 `&&`

```cpp
while(p != NULL || p->next != NULL)     // ❌
while(p != NULL && p->next != NULL)     // ✅
```

`||` 的右侧**不受左侧保护**：`p == NULL` 时 `p != NULL` 为假，程序照样去算 `p->next` → 空指针解引用。

**记忆法**：`&&` 才具备"左边不成立就不看右边"的短路语义。凡是"右边要依赖左边非空"的判断，只能用 `&&`。

```cpp
if (t != NULL && t->left != NULL)      // ✅
if (t != NULL || t->left != NULL)      // ❌ 右边会崩
```

这条在第 11 课遍历、第 10 课快慢指针里同样适用。

### 错法二：内层没让 `q` 前进

```cpp
while(q->next->next != NULL){
    q->next->next = p->next;   // ❌ 循环体里没有 q = q->next
    ...
}
```

`q` 永远停在起点，既走不到尾部，又反复改同一处指针，最后把链表改成一团。

### 错法三：接线顺序颠倒，接成自环

```cpp
q->next->next = p->next;    // ❌ 此时 q->next 是 p 的后继，等于让 p->next 指向自己
p->next = q->next;
q->next = NULL;             // 再一刀切断，后半段彻底丢失
```

**正确顺序：先摘、再接**

```cpp
NODE *last = q->next;       // ① 记下尾结点
q->next = NULL;             // ② 先把尾巴从原位置摘掉
last->next = p->next;       // ③ 尾巴指向 p 原来的后继
p->next = last;             // ④ p 指向尾巴
```

改指针前先把旧值存进临时变量，永远是链表题的第一原则。

### 错法四：找的是"尾结点"而不是"尾结点的前驱"

要摘掉最后一个结点，必须修改它**前驱**的 `next`。所以 `q` 应停在 `q->next->next == NULL` 的位置，此时 `q->next` 才是尾结点。

### 修正后的暴力版（已通过 2012 项测试）

```cpp
void ans(NODE *L){
    if (L == NULL) return;
    NODE *p = L->next;
    while (p != NULL && p->next != NULL){
        NODE *q = p;
        while (q->next->next != NULL) q = q->next;   // 找尾结点的前驱
        NODE *last = q->next;
        q->next = NULL;             // 先摘
        last->next = p->next;       // 再接
        p->next = last;
        p = last->next;             // p 跳过刚插入的尾巴
    }
}
```

### 复杂度对照

| 做法 | 时间 | 空间 |
|---|---|---|
| 反复找尾插入（本文） | **O(n²)** | O(1) |
| 快慢指针找中点 + 逆置后半 + 交替合并 | **O(n)** | O(1) |

暴力版逻辑直观、易调试，适合先写对；真题要求"时间尽可能高效"，O(n) 三步法才是标准答案。两者结果完全相同，可以用暴力版给 O(n) 版对拍。

## 十六、顺序存储二叉树判 BST：赋值当判断，父子当全局

**2022 真题**：数组存储的二叉树（`-1` 表示空结点），判断是否为二叉搜索树。

### 错误一：`=` 写成了 `==`

```cpp
if(T->SqBiTNode[i] = -1) continue;      // ❌ 赋值
```

后果是双重的：

- **把每个结点都改成 `-1`**，原始数据被彻底破坏
- `-1` 非零，条件恒真 → 所有结点都被跳过 → **函数无条件返回 true**

编译器给了明确提示：

```
warning: suggest parentheses around assignment used as truth value [-Wparentheses]
```

`-Wparentheses` 就是专门抓 `if (x = 常量)` 的。实测四个用例里两个非 BST 全被判成 `true`，而"调用后数组"全变成 `-1`，一眼就能看出赋值把数据毁了。

**习惯**：条件里的 `=` 永远只该是 `==`；编译器的 `-Wparentheses` 不要忽略。

### 错误二：只比较直接父子，判不出跨层违规

```cpp
if(左孩子 > 父) return false;
```

BST 要求**整棵子树**满足约束，不是只看相邻两层。反例：

```
        10
       /  \
      5    15
          /
         6        ← 在根的右子树里却小于根
```

`15 > 10` ✅、`6 < 15` ✅，父子全合格，但整棵树不是 BST。**父子比较永远发现不了这种"越级"违规。**

### 错误三：拿祖父的值当右孩子上界

```cpp
pass = T->SqBiTNode[(i+1)/2 - 1];        // 祖父
if(右孩子 > pass) return false;          // ❌
```

右孩子的上界是"从根下来、最近一个把该结点放在左子树方向的祖先值"，不是祖父。祖父自己可能还受着更小的上界约束，用它当界会漏判也可能误判。

### 错误四：`ElemNum` 当成数组容量

```cpp
T->SqBiTNode[2*i + 2]        // i 接近 ElemNum 时可能 ≥ 1000，越界读
```

`ElemNum` 是**有效结点个数**，不是数组长度。取孩子下标前必须先判 `k >= T->ElemNum`。

### 错误五：空树判成 false

空树是二叉搜索树，应返回 `true`。

### 正确解法：中序遍历必须严格递增

BST 的充要条件就是中序序列严格递增。数组存储的树，中序 = 左、自己、右：

```cpp
bool check(SqBiTree *T, int k, int &prev){
    if (k >= T->ElemNum || T->SqBiTNode[k] == -1) return true;
    if (!check(T, 2 * k + 1, prev)) return false;      // 左
    if (T->SqBiTNode[k] <= prev) return false;         // 中：严格递增
    prev = T->SqBiTNode[k];                            // 更新前驱
    return check(T, 2 * k + 2, prev);                  // 右
}

bool ans(SqBiTree *T){
    if (T == NULL) return true;
    int prev = INT_MIN;                                // <climits>
    return check(T, 0, prev);
}
```

两个要点：

- **`prev` 用引用传递**，整趟遍历共用同一个前驱；写成值传递，每层递归拿到副本，比较立刻失效
- **边界判断一次挡两件事**：`k >= ElemNum` 防越界，`== -1` 防空结点

### 对照写法：传上下界

```cpp
bool check(SqBiTree *T, int k, long long lo, long long hi){
    if (k >= T->ElemNum || T->SqBiTNode[k] == -1) return true;
    int v = T->SqBiTNode[k];
    if (v <= lo || v >= hi) return false;
    return check(T, 2*k+1, lo, v) && check(T, 2*k+2, v, hi);
}
```

每个结点都带着"祖先允许的取值区间"往下走，直观但参数多。两种写法在测试里互为对照。

### 判 BST 的通用结论

| 判据 | 是否充分 |
|---|---|
| 左孩子 < 父 < 右孩子 | ❌ 只看一层 |
| 中序序列严格递增 | ✅ 充要 |
| 每个结点落在 (lo, hi) 内 | ✅ 充要 |

重复值要留意：若定义允许相等，判据应改成非递减；上面的写法是**严格递增**（等值判 false）。

## 十七、无向图判欧拉路径：出度 + 入度 = 2 × 度

**2021 真题**：邻接矩阵存储的无向图，判断是否存在欧拉路径（EL 路径），存在返回 1，否则 0。

### 错误一：无向图里 `C[i] + R[i]` 恒为偶数

```cpp
if(G.Edge[i][j] != 0){ C[i]++; R[j]++; }        // 出度、入度
...
if((C[i] + R[i]) % 2 != 0) count++;             // ❌ 恒为假
```

无向图的邻接矩阵是**对称**的：一条边 `(i,j)` 会在 `[i][j]` 和 `[j][i]` 各记一次。所以：

```
C[i] = 出度 = 度
R[i] = 入度 = 度
C[i] + R[i] = 2 × 度      → 永远偶数
```

结果 `count` 恒为 0，`count <= 2` 恒成立，**函数无条件返回 1**。实测 9 个用例输出全是 1，4 个非欧拉图被误判。

> **结论：无向图里"出度"和"入度"是同一个东西，相加等于把度数翻倍，任何奇偶判断都会失效。**

### 错误二：变长 + 未初始化

```cpp
int R[G.numVertices];      // VLA，且是垃圾值
int C[G.numVertices];
C[i]++;                    // 在垃圾值上累加
```

- `-Wvla` 只在 `-pedantic` 下报，`-Wall` 看不见
- 未初始化是**未定义行为**：这次栈恰好为 0 所以"看起来稳定"，换环境可能整个翻转
- 一句话：**临时数组能删就删**

### 错误三：缺连通性判断

无向图存在欧拉路径的**充要条件**：

1. 奇度顶点数为 0 或 2
2. 非孤立顶点构成的子图**连通**

反例：两个互不相连的三角形，每个顶点度数为 2，奇度数 = 0，按纯奇度判据返回 1，但实际不存在走遍所有边的路径。2021 官方数据一般保证连通，知道这个缺口即可。

### 正确写法：一个数组都不用

```cpp
int IsExistEL(MGraph G){
    int odd = 0;
    for (int i = 0; i < G.numVertices; i++){
        int deg = 0;
        for (int j = 0; j < G.numVertices; j++)
            if (G.Edge[i][j] != 0) deg++;      // 无向图：第 i 行非零个数 = 度数
        if (deg % 2 != 0) odd++;
    }
    return (odd == 0 || odd == 2) ? 1 : 0;
}
```

时间 O(n²)（必须读完矩阵），空间 **O(1)**。

### 如果题目是有向图

判据完全不同，绝不能看"和的奇偶"：

| 条件 | 含义 |
|---|---|
| 至多一个顶点 `出度 - 入度 = 1` | 起点 |
| 至多一个顶点 `出度 - 入度 = -1` | 终点 |
| 其余顶点 `出度 == 入度` | 途经点 |

**判据是"出度与入度的差"，不是"和"。**

## 十八、未出现的最小正整数：快排内层不加上界

**2018 真题**：求 n 个整数中未出现的最小正整数，时间尽可能高效。

### 错误一：快排内层循环没有 `i < j` → 越界崩溃

```cpp
while(A[j] >= pivot) j--;      // ❌
while(A[i] <= pivot) i++;      // ❌
```

`pivot = A[L]`，所以 `A[L] >= pivot` 恒成立。当**所有元素都 ≥ pivot** 时：

- `j` 一路减到 `L`，仍然满足 `>= pivot`，继续减 → **越过左边界**
- `i` 一路加到 `R`，仍然满足 `<= pivot`，继续加 → **越过右边界**

实测 `{1,1,1}` 直接崩溃（`0xC0000005`），已排序数组同理。正确写法：

```cpp
while(i < j && A[j] >= pivot) j--;
while(i < j && A[i] <= pivot) i++;
```

> **快排自检：两个内层 while 是否都带 `i < j`？用"全相同"和"已排序"两组数据各跑一次。**

### 错误二：判据用错了对象

```cpp
if(i > A[j]) return i;      // ❌「存在比 i 小的数」≠「i 没出现」
```

题目问"i 是否出现过"，判据只能是 `A[j] == i`。`i > A[j]` 几乎总成立（只要有更小的数），所以函数总在第一轮就返回。

`{1,2,3}` 正确答案是 4，原写法返回 1。

### 错误三：`i` 从 0 开始

最小**正**整数从 1 起。数组含负数或 0 时，`0 > A[j]` 立刻成立 → 返回 0。

| 输入 | 原结果 | 正确 |
|---|---|---|
| `{-1,2,3}` | 0 | 1 |
| `{0}` | 0 | 1 |

### 错误四：又见 `n + 1` 越界

```cpp
for(int j = 0; j < n+1; j++) if(i > A[j])   // 读 A[n]
```

数组只有 `0 ~ n-1`。这个坑在 2009、2011、2018 各出现一次，**下标上界一律写 `n`（不取等）**。

### 错误五：兜底返回值

```cpp
return n;      // ❌ 1..n 全部出现时答案应为 n+1
```

### 保留排序思路的正确写法：`expect` 指针

排序后从小到大扫，维护"下一个应该出现的正整数"：

```cpp
int ans(int A[], int n){
    Qsort(A, 0, n-1);

    int start = 0;
    while(start < n && A[start] <= 0) start++;     // 跳过非正数

    int expect = 1;
    for(int i = start; i < n; i++){
        if(A[i] == expect)      expect++;          // 出现了，期望下一个
        else if(A[i] > expect)  return expect;     // 断档，就是答案
        // A[i] < expect 是重复值，跳过
    }
    return expect;                                 // 最大 n+1
}
```

三分支的含义要分清：

| 情况 | 处理 |
|---|---|
| `A[i] == expect` | 这个数有了，`expect++` |
| `A[i] > expect` | 中间断了，`expect` 就是答案 |
| `A[i] < expect` | 重复值（或不可能是答案的值），跳过 |

16 个手写用例 + 3000 个随机用例全部通过。

### 复杂度对比

| 方法 | 时间 | 空间 |
|---|---|---|
| 排序 + 扫描（本笔记写法） | O(n log n) | O(log n) 递归栈 |
| 标记数组 | **O(n)** | O(n) |
| 原地交换（桶思想） | **O(n)** | O(1) |

考点提示：题目问"**是否存在**"时优先想标记/哈希，不要条件反射排序。排序做的是"定序"，而这里只需要"查存在性"。

## 十九、唯一拓扑排序：`else return 0` 把判据颠倒了

**2024 真题**：有向图的邻接矩阵，判断是否存在**唯一**的拓扑排序序列，唯一返回 1。

核心判据一句话：**每一步入度为 0 的顶点必须恰好一个**。

| 本步入度 0 的顶点数 | 含义 |
|---|---|
| 0 个 | 剩下的顶点互相约束 → 有环，不存在拓扑序 |
| 1 个 | 下一个位置被唯一确定 |
| ≥ 2 个 | 谁先谁后都可以 → 拓扑序不唯一 |

### 错误一：完全没读输入图

```cpp
int A[n][n];                 // 声明后从未赋值
if(A[i][j] != 0) R[j]++;     // 数的是栈上垃圾值
```

整个函数从头到尾没用 `G.Edge`，等于对一个随机矩阵求拓扑序，结果与输入无关。应逐格拷贝，或直接读 `G.Edge`。

### 错误二：`else { return 0; }` 把判断逻辑写反

```cpp
for(int j = 0; j < n; j++){
    if(R[j] == 0 && !sign[j]) { ... }
    else { return 0; }       // ❌ 入度非 0 是正常状态
}
```

拓扑过程中绝大多数顶点入度都 `> 0`，这个 `else` 一碰到就返回 0。实测效果：**n ≥ 2 时一律返回 0**，连 `0→1→2` 这种最标准的唯一序列都判错（5 过 2 挂，其余全靠蒙对）。

正确写法是统计个数：

```cpp
int cnt = 0, pick = -1;
for(int i = 0; i < n; i++)
    if(!sign[i] && R[i] == 0){ cnt++; pick = i; }
if(cnt != 1) return 0;
```

### 错误三：重算入度前没清零

```cpp
// 开头清了一次 R，后面每轮直接 R[j] += 1
```

第二轮开始就是在上一轮的值上累加，入度被翻倍。重算前必须 `R[i] = 0`，或者改用"只减被删顶点的出边"（`R[k]--`），后者每轮 O(n)，不必重扫全图。

### 错误四：缺环检测

若剩余顶点入度全 `> 0`（有环），必须返回 0。原写法靠那个错误的 `else` 碰巧返回了 0，逻辑上并不成立。

### 错误五：三个变长数组

```cpp
int A[n][n];            // -Wvla
int R[n];               // -Wvla
bool sign[n] = {false}; // -Wvla
```

`-Wall` 不报，要 `-pedantic`。题目已给 `MAXV`，直接用 `int A[MAXV][MAXV]`。

### 错误六：内层 `i` 遮蔽外层 `i`

```cpp
for(int i = 0; ...){ for(int i = 0; ...){ } }   // -Wshadow
```

不影响结果，但极易看错作用域。外层改用 `step` 这类不同名字。

### 环境陷阱：`MAXV = 1000` 会栈溢出

`int Edge[1000][1000]` = 4 MB，而 `int uniquely(MGraph G)` 是**按值传参**，每次调用复制 4 MB 到栈上，Windows 默认栈 1 MB → `0xC00000FD`（栈溢出）。第一次运行原代码崩的就是这里，**不是算法错**。

| 做法 | 说明 |
|---|---|
| `MAXV` 取 100 | 最贴近官方答案，`MGraph` 只有 40 KB |
| 形参改 `const MGraph &G` | 不复制，但改了题目给的签名 |

### 复杂度

| 写法 | 时间 | 空间 |
|---|---|---|
| 原写法（每轮重扫全图，且 R 未清零） | O(n⁴) | O(n²) |
| 修正后（仍每轮重扫） | O(n³) | O(n²) |
| Kahn（`R[k]--` 只减出边） | **O(n²)** | O(n) |

15 个手写用例 + 3000 个随机 DAG + 2000 个随机带环图，全部通过。
